# Visual Identity Kit

## Goal

The visual identity should support the portfolio work rather than compete with it.

The priority is:

> Clear evidence, readable technical content, consistent presentation, and restrained visual styling.

---

## Brand Positioning

Primary focus:

- Generative AI Engineering
- Large Language Models
- RAG
- CAG
- Agentic AI
- NLP
- AI backend systems
- Production-focused AI workflows

The visual identity should feel:

- Technical
- Modern
- Clean
- Professional
- Minimal
- Reliable

It should not feel:

- Overdesigned
- Decorative for its own sake
- Like an AI-generated template
- Visually louder than the projects

---

## Typography

Use a simple two-level typography system.

### Headings

Use one modern sans-serif font for:

- Page titles
- Section headings
- Project titles

Headings should be bold enough to create hierarchy without becoming oversized.

### Body

Use a highly readable sans-serif font for:

- Project descriptions
- Case studies
- Technical explanations
- Contact information

Avoid using many different fonts.

Rule:

> Maximum two font families across the portfolio.

---

## Color System

Use a restrained palette.

### Primary

One main accent color for:

- Links
- Buttons
- Important highlights
- Active navigation states

### Neutral colors

Use neutral tones for:

- Background
- Main text
- Secondary text
- Borders
- Cards

### Rule

Avoid using many competing accent colors.

The project screenshots and technical diagrams should remain the strongest visual elements on the page.

---

## Layout

Use a consistent layout system across all pages.

Recommended rules:

- Consistent maximum content width
- Predictable section spacing
- Consistent card padding
- Clear alignment
- Enough whitespace between sections
- Avoid unnecessary floating elements

---

## Spacing

Use a small spacing scale consistently.

Example:

- Small: metadata and compact groups
- Medium: content inside cards
- Large: separation between sections
- Extra large: major page sections

Consistency is more important than the exact pixel values.

---

## Project Cards

Every project card should follow the same structure:

1. Project title
2. One-sentence problem or purpose
3. Short technology list
4. Real project screenshot or diagram
5. Key result
6. Link to case study / repository

The layout should not change dramatically between projects.

---

## Buttons and Links

Use a limited number of button styles.

### Primary action

Examples:

- View Project
- View Case Study

### Secondary action

Examples:

- GitHub
- Documentation
- Live Demo

Avoid multiple competing call-to-action styles.

---

## Image Style

Images should serve as evidence.

Preferred order:

1. Real product screenshot
2. Architecture or workflow diagram
3. Data visualization
4. Relevant technical illustration
5. AI-generated image only when it adds useful context

Do not use AI-generated images simply to fill empty space.

---

## AI Image Judgment Rule

Before using an AI-generated visual, ask:

1. Does it explain something useful?
2. Does it support the project evidence?
3. Is it visually consistent with the rest of the portfolio?
4. Would a real screenshot communicate the work better?

If the answer to the fourth question is yes, use the screenshot instead.

---

## Consistency Rules

Across the portfolio:

- Same heading hierarchy
- Same project card structure
- Same button styles
- Same spacing logic
- Same border radius
- Same image treatment
- Same tone of writing
- Same navigation behavior

A visitor should feel that every project belongs to the same portfolio.

---

## Frame, Not Upstage

The portfolio design is a frame around the engineering work.

The strongest visual element on a project page should usually be:

- the project itself,
- its architecture,
- its result,
- or its evidence,

not a decorative background or generated illustration.

The design succeeds when the visitor remembers the work more than the interface around it.
